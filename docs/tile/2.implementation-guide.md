# Implementation Guide — write your own TileLang kernel

This file is the **deletion template**. The TileLang implementations in
`nanovllm/kernels/tilelang/` are reference; you can replace them with
your own kernels by following the skeleton below.

> **How to use this file**: open `nanovllm/kernels/tilelang/<op>.py`,
> use the skeleton here as a checklist, and replace the body with your
> own implementation. The dispatch in `nanovllm/kernels/__init__.py`
> looks up the function by name, so as long as the signature matches
> the corresponding `_reference` version, the rest of the model
> continues to work.

## Skeleton: a single RMSNorm in TileLang

```python
import torch
import tilelang
from tilelang import language as T

from nanovllm.kernels.tilelang._compile_cache import get_compiled


# TODO Step 1: define the kernel signature.
#   - Inputs are T.Tensor[(static_shape), dtype].
#   - dtype is a string ("float16", "float32", ...) and matches the
#     torch dtype after stripping the "torch." prefix.
#   - The body of the kernel goes inside the `with T.Kernel(...)` block.
#   - Static shapes are required for TileLang compilation; if the
#     shape is dynamic, compile once per new shape and cache.
def _build_kernel(M: int, N: int, BLOCK_N: int, dtype: str, eps: float):
    @T.prim_func
    def rmsnorm_kernel(
        x: T.Tensor[(M, N), dtype],
        weight: T.Tensor[(N,), "float32"],
        y: T.Tensor[(M, N), dtype],
    ):
        # TODO Step 2: allocate shared / fragment buffers.
        #   - T.alloc_shared(shape, dtype) for shared memory.
        #   - T.alloc_fragment(shape, dtype) for register accumulators.
        #   - The dtype can differ from the wire dtype (e.g. compute in
        #     fp32 even when x is fp16) — this is what makes the numerical
        #     equivalence with the reference `torch.compile` kernel work.
        with T.Kernel(M, threads=BLOCK_N) as bx:
            acc = T.alloc_fragment((BLOCK_N,), "float32")
            T.fill(acc, 0.0)

            # TODO Step 3: implement the per-tile loop.
            #   - T.serial / T.ceildiv for compile-time loops.
            #   - T.arange(0, BLOCK_N) for thread indices.
            #   - T.copy(src, dst, mask=...) for masked load/store.
            for tile in T.serial(T.ceildiv(N, BLOCK_N)):
                offsets = tile * BLOCK_N + T.arange(0, BLOCK_N)
                mask = offsets < N
                x_l = T.alloc_shared((BLOCK_N,), "float32")
                T.copy(x[bx, offsets], x_l, mask=mask)
                acc += x_l * x_l

            sq = T.reduce_sum(acc, dim=0)
            rstd = T.rsqrt(sq / N + eps)

            for tile in T.serial(T.ceildiv(N, BLOCK_N)):
                offsets = tile * BLOCK_N + T.arange(0, BLOCK_N)
                mask = offsets < N
                x_l = T.alloc_shared((BLOCK_N,), "float32")
                T.copy(x[bx, offsets], x_l, mask=mask)
                out = (x_l * rstd).astype(dtype) * weight
                y_wire = T.alloc_shared((BLOCK_N,), dtype)
                T.copy(out, y_wire)
                T.copy(y_wire, y[bx, offsets], mask=mask)

    return tilelang.compile(rmsnorm_kernel, out_idx=[2], target="cuda")


# TODO Step 4: write the Python wrapper.
#   - The signature must match the corresponding function in
#     `nanovllm/kernels/_reference/`. Search for the function there
#     to find the exact argument list.
#   - Cache the compiled kernel by (op, dtype, shape) so repeated calls
#     don't re-trigger the JIT pipeline.
def rmsnorm(x: torch.Tensor, weight: torch.Tensor, eps: float) -> torch.Tensor:
    M, N = x.shape
    BLOCK_N = min(_next_pow2(N), 1024)
    weight32 = weight.float().contiguous()
    key = ("rmsnorm", x.dtype, M, N, BLOCK_N)
    compiled = get_compiled(key, lambda: _build_kernel(M, N, BLOCK_N, str(x.dtype).replace("torch.", ""), eps))
    y = torch.empty_like(x)
    compiled(x, weight32, y)
    return y
```

## Checklist

1. **Define `T.prim_func`** with the exact input/output tensor
   signatures. TileLang bakes the shapes into the compiled artifact;
   use a separate compile per shape.
2. **Allocate shared buffers** (`T.alloc_shared`) and register
   fragments (`T.alloc_fragment`). Match the dtype to the math —
   the router code paths in `_reference/` always accumulate in fp32.
3. **Implement the per-tile loop**. For elementwise / reduction ops
   this is a serial loop over chunks of the inner axis. For attention
   it's an outer loop over KV blocks.
4. **Write back to the output**. For dtypes that differ from the
   compute dtype, cast back with `.astype(dtype)` *before* the final
   `T.copy` to the global buffer.
5. **Pick `BLOCK_N` / `BLOCK_M`**. TileLang bakes these into the
   kernel. Reasonable defaults: 64, 128, 256, 512, 1024 — too large
   and you exceed shared memory; too small and you thrash.
6. **Cache the compiled kernel** by `(op, dtype, *static_dims)`.
   The `_compile_cache.get_compiled` helper is provided.
7. **Match the reference signature exactly** so the calling layer
   (`RMSNorm`, `SiluAndMul`, etc.) doesn't need to change.

## Things to watch out for

- **Compile cost**: TileLang's compile is slow (seconds). Don't
  recompile per call. The cache is keyed on shape; if you change
  shape every call, you'll pay this cost every call.
- **CUDA graph capture**: TileLang-compiled kernels are usually
  capture-friendly, but if your kernel does any host-side branching
  on the captured shape, graph capture will fail. Compile the right
  shape *before* the capture loop.
- **Mask semantics**: `T.copy(..., mask=cond)` writes only when
  `cond` is true. Outside the masked positions, the destination is
  unchanged.
- **Reduction tiles**: `T.reduce_sum(..., dim=0)` writes a 0-D
  fragment; you can't index into it. Use `T.alloc_fragment` to
  spill it into shared memory before indexing.
- **Threads vs elements**: `T.Kernel(M, threads=N)` launches M
  blocks with N threads each. The thread index is implicit — you
  use `T.arange(0, N)` to build per-thread offsets.
