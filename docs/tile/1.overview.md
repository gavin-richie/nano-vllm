# TileLang backend overview

This documentation describes the TileLang kernel backend added to
`nano-vllm`. The backend is **opt-in** — `Config.backend = "triton"` (the
default) preserves the original behavior bit-for-bit, while `"tilelang"`
swaps in TileLang implementations of the seven operators in scope.

## Why TileLang here?

TileLang is a tile-based kernel language that lowers through TVM. It
gives us explicit control over shared memory, register layout, and
tile-shape, which makes it easier to express the small, fused kernels
that dominate per-token cost in a transformer (RMSNorm, SwiGLU, RoPE,
paged-KV writes). Whether it ends up faster than the existing
`torch.compile` / `flash_attn` paths is an empirical question the
benchmarks in `tests/bench_*.py` are designed to answer.

## Operators in scope


| Operator                  | Reference backend                                 | TileLang backend                                   |
| --------------------------- | --------------------------------------------------- | ---------------------------------------------------- |
| `rmsnorm`                 | `torch.compile` in `nanovllm/layers/layernorm.py` | `nanovllm/kernels/tilelang/layernorm.py`           |
| `add_rmsnorm`             | `torch.compile` (fused residual + RMSNorm)        | `nanovllm/kernels/tilelang/layernorm.py`           |
| `silu_and_mul`            | `torch.compile` (SwiGLU)                          | `nanovllm/kernels/tilelang/activation.py`          |
| `apply_rotary_emb`        | `torch.compile` (RoPE)                            | `nanovllm/kernels/tilelang/rotary_embedding.py`    |
| `store_kvcache`           | `@triton.jit` (only existing Triton kernel)       | `nanovllm/kernels/tilelang/store_kvcache.py`       |
| `flash_attn_varlen`       | `flash_attn` paged+varlen                         | `nanovllm/kernels/tilelang/attention.py` (Phase 3) |
| `flash_attn_with_kvcache` | `flash_attn` paged+kvcache                        | `nanovllm/kernels/tilelang/attention.py` (Phase 3) |

`F.linear` (matmul), the LM head, the embedding, and the sampler are
**not** in scope — they use cuBLAS via `F.linear` and are not where
per-token time is spent.

## How to switch backends

```python
from nanovllm import LLM, SamplingParams

# Original Triton / torch.compile / flash_attn path (default).
llm = LLM("/path/to/qwen3")

# TileLang path.
llm = LLM("/path/to/qwen3", backend="tilelang")
```

`backend` is a field on `nanovllm.Config`. Errors raise early in
`Config.__post_init__`. If `tilelang` is not installed, the import
error happens lazily at the first call into the factory — making the
triton backend remain usable even without the TileLang package.

## Compatibility caveats

- **CUDA graphs**: the decode path uses `torch.cuda.CUDAGraph` capture.
  TileLang-compiled kernels are usually graph-capturable, but the
  compile-once-per-shape contract must be honoured (no runtime
  dispatch on the shape). See `notes/attention/notes.md` for the
  known limitation and the fallback.
- **Paged KV + varlen attention**: the most complex op. The first
  cut delegates to the upstream `flash_attn` package; the TileLang
  version is Phase 3 work.
- **Pin version**: `tilelang>=0.1.13,<0.2`. The TileLang API moves
  between minor versions; if you upgrade, expect some imports to
  need refactoring.
